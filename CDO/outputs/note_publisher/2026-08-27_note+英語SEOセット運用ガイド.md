# note + 英語SEOページ セット運用ガイド（CDO・2026-08-27）

## なぜセットにするのか（North Star）
North Star = **海外読者に高岡・氷見・富山の記事を読ませる**。
- note記事＝日本語主体。海外流入は Reddit/X 投稿（人手・owner判断）に依存し、詰まりやすい。
- **英語SEOページ（apps/toyama-guide/）＝Google検索経由で海外読者が直接到達**。code だけで作れ、人手・note URL に依存しない。
- → **新記事を作るたびに「英語SEOページ」も1枚出す**のを標準にすれば、公開のたびに海外流入の入口が自動で増える。

## 標準セット（新規note記事1本につき）
1. **note記事**（日本語・`## タイトル`＋`## 本文` コードブロック形式・drafts/queue 投函）
2. **英語SEOページ**（`apps/toyama-guide/en-<slug>.html`）
   - 雛形: `CDO/outputs/note_publisher/en_seo_page_template.html` の `{{...}}` を置換
   - 記事の English Summary を土台に、H2を3〜5本へ展開（600〜900語目安）
   - fact-checkノート必須（A5）・A4（地区名/店名/個人名なし）
3. **英語ハブへの内部リンク**（`en.html` の該当クラスタに1行 `<br><a href="en-<slug>.html">…→</a>`）
   - フード→en-food/en-toyama-black 付近／季節→en-autumn 付近／実用→en-money 付近／場所→該当地名付近
4. （任意）日本語版ページ `ja-<slug>.html` … 重要記事のみ。作る場合は en↔ja の hreflang を相互に張り、`index.html` 読みものセクションにも1行追加。

## 重複回避（着手前に必ず）
```bash
ls apps/toyama-guide/en-*<keyword>*     # 既存ページの有無
grep -rl "<題材>" CMO/outputs/           # note側の既存
```
既存 en-*.html と主題が被る場合は**角度を変える or 作らない**（薄い重複ページはSEOで逆効果）。

## 品質チェック（公開前・実機検証）
- HTML妥当性: doctype / `</html>` / `</head></body>` / `<title>` / canonical / hreflang / JSON-LD / ebook CTA / `<ul>`閉じ
- hreflang: EN単独なら en+x-default を self。ja版ありなら en↔ja 相互＋x-defaultはenへ。
- 内部リンク: en.html（+必要ならindex.html）に追加したか。
- 検証スニペット例:
```bash
python3 - <<'PY'
import re; t=open("apps/toyama-guide/en-<slug>.html",encoding="utf-8").read()
for k,v in {"title":"<title>" in t,"canonical":'rel="canonical"' in t,
 "jsonld":"application/ld+json" in t,"ul":t.count("<ul>")==t.count("</ul>")}.items():
    print(("OK " if v else "NG ")+k)
PY
```

## 既存実装例（このガイドと同時に作成）
- `en-tap-water.html` / `ja-tap-water.html`（水道水・en↔ja相互）
- `en-takaoka-croquette.html`（高岡コロッケ・EN単独）
- `en-rice-fields.html`（収穫前の田んぼ・EN単独）

## デプロイ
apps/toyama-guide/ は GitHub Pages で `…github.io/agent-team/toyama/` として配信済み（既存150+ページと同経路）。
push すれば同様に配信される。**新規ファイルは既存と同じディレクトリ・同じテンプレなら追加設定不要。**
